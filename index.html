📖 Hardware & Arduino Code Setup Guide For Beginners

This live visual editor focuses exclusively on rendering display drawing commands. To run this code on physical hardware, your C++ sketch requires proper driver includes, pin mappings, and initialization loops.

1. Hardware SPI & Pin Definitions

MOSI and SCK must use your board's hardware SPI pins (they come from the MCU SPI peripheral and are not easy to move). Look up the default SPI pins for your board (ESP32, RP2040, Arduino, etc.).

CS, DC, RST, BUSY are chosen by you in the GxEPD2 constructor — most free GPIOs work, with a few practical limits:

  • SPI pins can be shared with SD-card, but avoid sharing pins with other peripherials unless you know what you are doing.
  • Avoid pins that are input-only for outputs like CS, DC, or RST (some boards have a few ADC / input-only pins).
  • Be careful with boot / strapping pins. They can still work, but the wrong level at reset can cause odd boot behavior.

When in doubt, start from a known-good example for your board + panel, then change one pin at a time if needed.

2. Display Class & Driver Setup

Make sure you have installed the GxEPD2 library, if you are using 4 grey display, use the GxEPD2_4G library. Select the correct display driver matching your panel controller (e.g. GxEPD2_154_D67) and display class header (GxEPD2_BW, GxEPD2_3C, GxEPD2_4C, GxEPD2_7C, etc.). Consult the GxEPD2 display selection header files for the driver class.

3. Window Setup Must Happen Before firstPage()

setFullWindow() or setPartialWindow(x, y, w, h) must be called before firstPage(). They configure the update region for the following paged draw loop. Calling them inside the do { ... } while (nextPage()) body does not work as expected on hardware.

This live editor still draws shapes over the full canvas for layout preview — the dashed PartialWindow box is only a visual guide, not a clip region.

4. Rotation

Use display.setRotation(1) // 0-3 after init() to change drawing direction / swap logical width and height. This editor does not simulate rotation — set the toolbar W/H to match your rotated dimensions when previewing.

5. Full Arduino Sketch Structure

Paged drawing must occur inside a firstPage() / nextPage() loop. Always call display.powerOff() to power the panel down to avoid damaging the panel and saving power:

#include <GxEPD2_BW.h> // The display class e.g. BW/3C/4C/7C


GxEPD2_BW<GxEPD2_154_D67, GxEPD2_154_D67::HEIGHT> display(
  GxEPD2_154_D67(/*CS=*/ 15, /*DC=*/ 27, /*RST=*/ 26, /*BUSY=*/ 25));
  
//GxEPD2_DISPLAY_CLASS display(GxEPD2_DRIVER_CLASS(CS, DC, RST, BUSY));
//Consult GxEPD2 examples if you are unsure about this


void setup() {
  display.init(115200, true, 2, false);
  // display.setRotation(1); // optional: 0,1,2,3

  display.setFullWindow();   // MUST be before firstPage()
  // display.setPartialWindow(x, y, w, h); // Or partial update window if your display supports it, some manufacturers recommend a full refresh every 5 partial refresh and they warn that exceeding this limit too often can cause permanent abnormal display states or irreversible uneven fading on smaller panels. I personally only do a full refresh for my e-ink clock twice per hour (1 in 30) which seem to be find after 2 years but adjust the refreshes at your own risk.

  display.firstPage();
  do {
    // --- Paste Live Editor Output Here ---
    display.fillScreen(GxEPD_WHITE);
    display.setTextColor(GxEPD_BLACK);
    display.setTextSize(1);
    display.setCursor(10, 20);
    display.print("Hello World!");
  } while (display.nextPage());

  display.powerOff(); // prevent burn-in / save power
}

void loop() {}
🦉 About this Editor

This is a standalone browser-based live preview editor for the GxEPD2 library for use with e-paper / e-ink displays. Write code and the live viewer renders it while the parser warns you of syntax errors; or insert and draw on the canvas and get instant code for your display.

Features

  • Live canvas preview for BW, 3-colour, 4-colour, 6-colour (Spectra) and 7-colour (ACeP) e-ink displays
  • Supports most GxEPD2 / Adafruit_GFX drawing primitives, text, simple variables and for-loops (experimental)
  • Because the GxEPD2 underlying rendering is Adafruit_GFX, most of this tool should work for LCD displays using Adafruit_GFX as well (just change the colors)
  • Drag objects on the canvas or edit them in the properties panel
  • Insert objects directly with the insert tools
  • Out-of-bounds, colour-compatibility and missing-setup warnings
  • Export PNG, copy clean code (comments stripped) for your projects

Known limitations

  • Text uses approximate 5×7 GFX metrics and cannot fully emulate the GFX font; The text will look slightly different on the actual panel
  • display.getTextBounds is not supported for the same reason
  • Bitmaps are shown as labelled placeholders (no pixel data)
  • Rotation, custom fonts, and full hardware init are not simulated — see the Guide
  • Custom / user-defined functions are not supported (only the built-in GxEPD2 / GFX drawing commands, simple variables, and basic for/while loops)
